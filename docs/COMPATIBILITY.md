# 通用 Skill 与执行层适配

[简体中文](COMPATIBILITY.md) · [English](en/COMPATIBILITY.md)

目标：同一套 Skill、偏好约定与教程，运行时按系统适配调用层。文字说明可以共用，附带脚本的兼容性要分别验证。

## 当前代码基线

Bridge 使用 Python 标准库、`fcntl` 文件锁、POSIX 进程组和文件权限，并读取 macOS 管理配置路径。开发调度器使用自有 YAML 子集，不依赖运行时 PyYAML。最低 Python 版本声明为 3.9；是否覆盖各受支持版本，需按下述矩阵重测。

当前实际验证过的官方 CLI 是 2.1.285。版本、二进制架构和完整性哈希应在安装者机器上独立绑定；不能复制作者 ARM 机器的哈希，也不能简单给任意 PATH 程序算哈希就称为“官方来源已确认”。

## 待实现的平台接口

| 能力 | macOS／Linux | Windows 原生 | 验收重点 |
| --- | --- | --- | --- |
| 解释器与 CLI 定位 | 从显式安装路径调用，不硬编码作者目录 | 支持本机 Python／官方 CLI 的绝对路径 | 空格、Unicode、软链接与来源证据 |
| 项目互斥 | POSIX 锁 | Windows 锁适配 | 双调用拒绝、崩溃后释放 |
| 超时与进程清理 | POSIX 进程组 | Windows 进程树适配 | 无遗留子进程、不重试未知结果 |
| 私有配置与权限 | Unix 权限、无符号链接规则 | Windows ACL／重解析点适配 | 不因移植丢失保护 |
| 管理设置检查 | 每平台适用路径 | 官方 Windows 路径 | Provider／认证／强度设置覆盖 |
| 时间与路径 | 明确时区、平台路径解析 | 时区数据库与原生路径适配 | 不把作者所在地当朋友所在地 |

**以上是实施清单，不是已完成的跨平台支持声明。** 当前 POSIX 脚本不能直接被标成 Windows 原生可用。WSL 内运行也需验证路径、项目范围与宿主调用方式；不能借 WSL 的存在声称 Windows 原生已通过。

## 验证矩阵

1. 各平台离线运行失败、锁、路径、权限、超时和状态保存用例。
2. 每个候选官方 CLI 版本检查参数支持、订阅认证、真实返回模型和恢复行为。
3. 干净安装时只安装 Skill 目录，确认脚本／模板／教程齐全。
4. macOS、Linux／WSL、Windows 原生分别做一次用户授权的真实咨询和连续追问，单独标记结果。
5. 教程与自助路由在全新聊天验收。

只通过离线 CI 不等于真实官方 CLI 或桌面调用通过。未知 CLI 版本不通过一句“用户同意”就跳过已有检查；在发布前补充版本能力验证。官方 CLI 的系统支持见 [设置文档](https://code.claude.com/docs/en/setup)。
