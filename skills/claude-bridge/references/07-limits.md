# 支持范围与限制

[简体中文](07-limits.md) · [English](en/07-limits.md)

Skill 负责规定 Codex 怎么调用 Claude、怎么核对结果；附带的 Python Bridge 负责在本机执行、检查、记录会话元数据和交接。文字说明各系统通用，程序对操作系统、官方 CLI、认证和 Codex 宿主工具有要求。

## 验证到哪了

| 范围 | 现状 |
| --- | --- |
| 维护者现用的 macOS 环境 | 做过真实咨询、连续会话和开发交接；现行回执规则也有真实调用的记录。官方 CLI 2.1.285；已有离线基线：Bridge 84/84（fake CLI），调度器 48/48（任务生命周期和确定性逻辑） |
| macOS 新机器安装 | 有教程和打包方案，但还没在新机器上验证安装、登录和路由 |
| Linux、WSL | 设计上基于 POSIX，有望适配；安装、权限、路径和真实调用都还要验证 |
| Windows 原生 | 现在的 Bridge 用了 POSIX 能力，代码和安装都要适配，原生支持还没做完 |
| 普通帮助和教程 | Codex 按需读本地参考文件，不会为了帮助去调用 Claude；新安装后的发现路线还要验证 |
| Team/Enterprise、API 或第三方认证 | 现在的订阅检查不支持，也不会自动 fallback |

官方 Claude Code 支持哪些系统，不代表这个 Bridge 在那些系统上都能跑。以后更新这张表，要有能复现的对应测试，并区分离线测试、真实 CLI、桌面端路由和应用关闭后的恢复。

## 模型与账号

你需要自己的官方 Claude Code 登录，以及当前 Bridge 检查接受的 claude.ai Pro 或 Max 订阅。装 Skill 不送账号、额度或模型权限。Sonnet、Opus 能不能用，看你的官方 CLI 和账号实际返回什么。

Bridge 不建立 API Provider，不创建 API Key，不购买额外 usage，不开启 Billing，额度用完或调用失败时也不会改走付费 API。费用已关闭的记录，来自你本人的确认，脚本没有直接读取账户 Billing。

## 权限和材料

装好 Skill 不等于授权它扫描任意项目、初始化 `.ai/` 或发送项目内容。每次都要有明确的项目、任务、材料范围和你已有的授权；缺哪样，Codex 会先问。

`consult` 在这次调用里禁用内置工具和 MCP，只分析你提供的材料。需要工具或改文件，用 `standard`。正常的启动钩子等环境行为，不在被禁用之列。

官方的权限机制保留不动，不用跳过权限的参数，也不用全局通配授权。私有任务文件和 Bridge 日志不进公开交付物，日志只记必要的运行元数据，但这不能保证任何敏感输入都适合公开。官方的原生会话记录由官方 CLI 管理，和 Bridge 的元数据日志是分开的。

## 连续使用

持续授权只来自你在当前聊天里的明确表态，只管同一个项目、同一个话题。缓存不是授权。切回 Codex、换项目、开新聊天，都要重新判断。两个 Codex 聊天可能用到同一个项目的 Claude 会话，需要隔离的话，请明确要求新建会话。

恢复会话不代表共享全部上下文。增量基线只覆盖规定的项目摘要、规则和 Git 快照，不会自动读取所有业务文件。模型嘴上说“我记得”，也代替不了对会话和实际内容接续的检验。

## 延迟与验收

Skill 能减少 Codex 开始处理之后的重复准备，但拦不住桌面端的原生输入，改不了 Codex 原生强度，保证不了固定的响应时间，也消除不了长聊天本身的开销。CLI wall 和端到端等待要分开看。这个版本没有流式首 token 计时。

维护者机器上的测试结果，证明不了你的账号、系统和安装也能直接通过。装完以后，最小的验收包括：Skill 能被发现、环境检查通过、一次真实调用的回执，需要连续使用的话再加会话接续测试。输出看着正确，也不能说明发布、部署或付款已经完成。
