# 升级、备份与卸载

[简体中文](06-update-uninstall.md) · [English](en/06-update-uninstall.md)

当前仓库的安装、升级和卸载接口仍需以实际脚本与发布版本为准。本页给出可审查的人工流程，不把拟议命令写成已经存在的功能。

## 升级前

1. 确认没有仍在运行的 Bridge 调用，也没有 Agent 正在修改同一项目。
2. 记录当前仓库版本或 commit、完整 Skill 安装目录和本机配置位置。
3. 备份现有 Skill、runtime 和本机修改；备份不进入公开仓库。
4. 阅读新版本变更、系统支持与迁移要求，比较文件差异；保留使用者修改，不覆盖已有同名文件。

向 Codex 提出明确范围即可：

```text
$claude-bridge 帮我检查这个新版本与现有安装的差异。
先生成升级步骤和备份清单；在我明确要求应用之前不要替换文件或升级官方 CLI。
```

如果用户已经明确要求执行升级，应在该范围内完成准备和替换，不添加重复确认。涉及原授权以外的账号、系统或项目变更时才澄清。

## 应用与验证

替换时使用已核对的版本；Skill、程序、配置模板和教程作为一个安装单元保持一致。本机 runtime、费用确认和 CLI 固定路径由使用者自己保留或迁移，不用作者运行配置覆盖。

官方 Claude Code 升级是另一项操作。Bridge 可能固定版本及哈希；CLI 升级后应重新核对本机官方文件、所需参数、版本和完整性，再更新固定配置。不要为了避免错误而移除 guard，也不要把更新 Bridge 当作自动授权更新全机软件。

先运行格式/离线检查与 `doctor`，再在已授权测试项目做一次真实咨询并核对回执。连续使用者再验收同 Session 的第二轮。offline 或 `--dry-run` 通过不能替代真实调用；新系统和新安装路线需独立记录通过或待验证。

## 回退

出现异常时先保留当前运行证据，检查是否有升级后新增的用户修改。确认待恢复文件确属此次安装管理范围，再从备份恢复 Skill 及相应本机配置。不要使用 `git reset --hard`、`git clean -fd` 或全局清理命令来回退。

恢复旧 Skill 不意味着 Claude 会话、项目交接内容和外部任务自动回滚。对项目状态分别核对，不用旧缓存冒充新的恢复成功。

## 卸载

先停止调用，确认安装位置和由安装流程管理的具体文件。如果只想停止路由，在当前聊天说“切回 Codex”；这无需卸载。

正式卸载时先归档或移走本次安装的 `claude-bridge` 目录，并按实际安装清单处理专属于这份工具的入口。存在使用者修改时先保存。可选 `dev-orchestrator` 若单独安装，按其自己的清单处理，不连带删除其他 Skills、MCP 或 Agent 配置。

保留以下内容，除非用户对具体清理另有明确要求：

- 官方 Claude Code 安装、登录、账号配置及原生会话历史。
- Codex 登录、聊天历史和其他工具配置。
- 各项目已有 `.ai/` 摘要、决定、交接、日志、备份和会话元数据。
- 项目代码、未提交工作和 Git 历史。

项目 `.ai/` 可能包含其他工具或人工维护的内容，不能因为卸载 Skill 就整体删除。需要清理时逐项确认所有权与保留价值，优先归档。
