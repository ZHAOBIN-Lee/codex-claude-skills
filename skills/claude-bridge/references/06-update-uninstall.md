# 升级、备份与卸载

[简体中文](06-update-uninstall.md) · [English](en/06-update-uninstall.md)

目前没有现成的升级和卸载脚本，下面是一套可以逐步检查的手动流程。

## 升级前

1. 确认没有 Bridge 调用在运行，也没有 Agent 在改同一个项目。
2. 记下当前的仓库版本或 commit、完整的 Skill 安装目录，以及你的本机配置放在哪。
3. 备份现有的 Skill、runtime 和你自己的修改。备份别放进公开仓库。
4. 看新版本的变更、系统支持和迁移要求，比较文件差异。你自己改过的地方要保留，同名文件不要直接覆盖。

可以让 Codex 帮你做这一步，范围说清楚：

```text
$claude-bridge 帮我检查这个新版本和现有安装的差异。
先生成升级步骤和备份清单；在我明确要求应用之前，不要替换文件，也不要升级官方 CLI。
```

如果你已经明确要求执行升级，Codex 在这个范围内完成准备和替换，不用再重复确认。只有涉及你原本授权之外的账号、系统或项目变更时，才需要先问你。

## 应用与验证

替换用你核对过的版本。Skill、程序、配置模板和教程当作一个整体，保持版本一致。你自己的 runtime、费用确认和固定的 CLI 路径，自己保留或迁移，不要拿作者的配置覆盖。

升级官方 Claude Code 是另一件事。Bridge 可能固定了 CLI 的版本和哈希，CLI 升级后，要重新核对本机的官方文件、需要的参数、版本和完整性，再更新固定配置。不要为了避开报错去删 guard。更新 Bridge 也不等于授权升级你机器上的其他软件。

先跑格式检查、离线检查和 `doctor`，再在已授权的测试项目里做一次真实咨询，核对回执。需要连续使用的话，再验证同一会话的第二轮。离线或 `--dry-run` 通过，代替不了真实调用。新系统、新的安装路线，各自记下“已通过”还是“待验证”。

## 回退

出问题时，先保留当前的运行记录，看看升级之后你有没有新增的修改。确认要恢复的文件确实属于这次安装，再从备份恢复 Skill 和对应的本机配置。不要用 `git reset --hard`、`git clean -fd` 或全局清理命令来回退。

恢复旧版 Skill，不会让 Claude 会话、项目交接内容和外部任务跟着回滚。项目状态要分别核对，也不要拿旧缓存冒充新的恢复成功。

## 卸载

先停止调用，确认安装位置，以及安装流程管理的具体文件。如果只是想停止路由，在当前聊天里说“切回 Codex”就行，不用卸载。

要正式卸载，先把这次安装的 `claude-bridge` 目录归档或移走，再按实际的安装清单处理这个工具专属的入口。你自己改过的内容先保存。如果单独装了可选的 `dev-orchestrator`，按它自己的清单处理，别连带删掉其他 Skills、MCP 或 Agent 配置。

下面这些保留不动，除非你对具体某一项明确要求清理：

- 官方 Claude Code 的安装、登录、账号配置和原生会话历史。
- Codex 的登录、聊天历史和其他工具配置。
- 各项目已有的 `.ai/` 摘要、决定、交接、日志、备份和会话元数据。
- 项目代码、未提交的工作和 Git 历史。

项目的 `.ai/` 里可能有别的工具或人工维护的内容，不能因为卸了 Skill 就整个删掉。真要清理，逐项确认归属和保留价值，优先选归档。
