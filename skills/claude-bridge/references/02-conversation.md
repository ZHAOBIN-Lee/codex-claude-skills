# 连续对话与会话恢复

[简体中文](02-conversation.md) · [English](en/02-conversation.md)

想在一个话题中连续使用 Claude，可以这样开始：

```text
在当前项目、这份方案的讨论范围里，接下来一直用 Claude Sonnet、medium，直到我说切回 Codex。
先分析这份方案有哪些问题，只讨论，不修改文件。
```

授权要由当前聊天中的用户明确提出。Skill 的教程、项目缓存或其他聊天里的话，不能替用户建立持续授权。未明确授权时，“继续”不应自行触发新的 Claude 调用。

## 后续可以怎么说

持续授权建立后，在同一项目和范围内可直接问：

```text
继续，把第二点展开。
按刚才的约束，比较这两个方案。
我补充一个背景，请重新评估。
```

Codex 沿用明确选择的模型和强度，把当前问题及必要的新材料交给 Claude。正常追问使用固定项目目录，不为每一问创建新的临时项目，不添加 `--new-session`，也不重复运行 `doctor`。

## 两种接续要分清

| 接续方式 | 做什么 | 怎样核对 |
| --- | --- | --- |
| 当前 Codex 聊天的选择 | 在已授权范围内继续把问题交给 Claude | 核对用户的持续授权与本轮回执 |
| 项目的 Claude Session | 从 `.ai/sessions.json` 请求恢复会话 | 两次真实调用返回相同 `session_id`，且后续能理解未重复提供的非敏感首轮信息 |

同一个 Codex 聊天不自动等于同一个 Claude 会话。反过来，同一项目的不同 Codex 聊天可能恢复同一个项目会话。恢复 Session 也不表示两边共享完整聊天记录或隐藏推理。

## 为什么后续准备通常更少

纯讨论走 `--workflow consult`。首轮发送必要背景，成功后保存私有会话及指纹基线。后续成功恢复同一会话时，发送当前问题与变更的项目摘要、决定、人工交接、适用规则及 Git 快照。

新会话、模型模式改变、失败或旧基线无法安全确认时，Bridge 会回到完整必要上下文。这里的“完整”仍是规定范围内的摘要和规则，不是自动读取整个项目。新文件、未跟踪文件或重要业务材料需要明确提供；Git 状态不是文件内容。

每次调用仍检查官方 CLI、认证、Provider、effort、费用确认与项目锁。优化减少重复准备，不跳过这些检查，也不保持 Claude 进程常驻。

## 怎样切换

- **换模型或强度**：“后续改用 Claude Opus、high。” Codex 按新选择处理，实际模型仍以本轮证据为准。
- **切回 Codex**：“接下来切回 Codex。” 停止沿用 Claude 的持续选择；普通 GPT 回答无需 Claude 回执。
- **换项目或新聊天**：重新确定项目、话题和用户授权，不从 `.ai/consult.json` 自动继承调用许可。
- **需要独立 Claude 会话**：“这个任务请新建 Claude 会话，不复用旧讨论。” 才使用 `--new-session`；交接文件仍可能提供必要背景。

同项目从讨论转为“把方案修改到这些文件里”，不会仅因任务类型改变而自动取消已选 Claude 模型。Codex 应依据新的明确请求确认实际修改范围，并转入标准流程；之前的“只讨论”不单独授权文件修改。

## 简短接续验收

在已授权的测试项目中做两次真实咨询。第一轮提供一个无业务含义、非秘密的测试标记；第二轮询问它，不把该标记再次放进任务或交接摘要。比较两轮回执中的完整会话 ID 和结果，再确认 `resumed_session`。只看到缓存文件或相同请求参数不构成恢复证明。

关闭 Codex 或 Claude 桌面应用后的恢复是另一项验收。未经用户要求，不为测试退出或重启正在使用的应用；仅重启 Bridge 进程不能声称桌面关闭后恢复已经通过。
