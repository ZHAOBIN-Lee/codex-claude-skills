# 连续对话与会话恢复

[简体中文](02-conversation.md) · [English](en/02-conversation.md)

想围绕一个话题一直用 Claude，可以这样开头：

```text
在当前项目、这份方案的讨论范围里，接下来一直用 Claude Sonnet、medium，直到我说切回 Codex。
先分析这份方案有哪些问题，只讨论，不修改文件。
```

这句话要你在当前聊天里自己说。教程里的示例、项目缓存、别的聊天里说过的话，都不算数。你没说过，单独一句“继续”不会让 Codex 去调用 Claude。

## 之后怎么追问

授权说过之后，在同一个项目、同一个话题里，直接说：

```text
继续，把第二点展开。
按刚才的约束，比较这两个方案。
我补充一个背景，请重新评估。
```

Codex 会沿用你选的模型和强度，把当前问题和新增的材料交给 Claude。追问用同一个项目目录，不用为每个问题建临时项目，不加 `--new-session`，也不用每次先跑 `doctor`。

## 两种“接续”

| 接续的是什么 | 它做什么 | 怎么确认 |
| --- | --- | --- |
| 当前 Codex 聊天里的选择 | 在你授权的范围内继续把问题交给 Claude | 你的持续授权，加这次调用的回执 |
| 项目的 Claude 会话 | 按 `.ai/sessions.json` 请求恢复会话 | 两次真实调用返回同一个 `session_id`，第二次能理解第一次说过、之后没再提供的非敏感内容 |

一个 Codex 聊天不一定对应一个 Claude 会话。同一项目的不同 Codex 聊天，可能恢复到同一个项目会话。恢复会话也不意味着两边共享完整的聊天记录或隐藏推理。

## 为什么后面几轮准备得少

纯讨论用 `--workflow consult`。第一轮发送必要的背景，成功后保存私有的会话记录和指纹基线。之后成功恢复同一个会话时，只发送当前问题，以及有变化的项目摘要、决定、人工交接、适用规则和 Git 快照。

换了新会话、换了模型模式、上一轮失败，或者旧基线没法确认安全，Bridge 就退回到发送完整的必要上下文。这里的“完整”指规定范围内的摘要和规则，不是把整个项目读一遍。新文件、没被 Git 跟踪的文件、重要的业务材料，要你明确提供。Git 状态只告诉 Claude 哪些文件变了，没有文件内容。

每次调用仍会检查官方 CLI、认证、Provider、强度设置、费用确认和项目锁。省掉的是重复准备，检查一项不少，Claude 进程也不会常驻后台。

## 怎么切换

- **换模型或强度**：说“后续改用 Claude Opus、high”。实际用了哪个模型，仍以那次调用的回执为准。
- **切回 Codex**：说“接下来切回 Codex”。Codex 不再沿用 Claude 的选择，普通 GPT 回答不用附 Claude 回执。
- **换项目或开新聊天**：重新说清项目、话题和授权。`.ai/consult.json` 的存在不代表你同意调用。
- **要一个独立的 Claude 会话**：说“这个任务请新建 Claude 会话，不复用旧讨论”。这时才用 `--new-session`，交接文件仍可能提供必要的背景。

同一个项目里，从讨论转到“把方案改写进这些文件”，之前选的 Claude 模型会保留。Codex 要根据你的新请求确认到底改哪些文件，并转入标准流程。之前的“只讨论”不算改文件的授权。

## 快速验证接续是否生效

在已授权的测试项目里做两次真实咨询。第一次给一个没有业务含义、不敏感的测试标记；第二次问这个标记是什么，别把它再写进任务或交接摘要。对比两次回执里完整的会话 ID 和回答，再确认 `resumed_session`。只看到缓存文件、或者请求参数一样，证明不了会话真的恢复了。

关掉 Codex 或 Claude 桌面应用之后还能不能恢复，是另一项验证。你没要求的话，别为了测试去退出或重启正在用的应用。只重启 Bridge 进程，不能说明桌面应用关闭后的恢复没问题。
